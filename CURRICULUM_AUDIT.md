# FinQuest India curriculum and interaction audit

Audit date: 2026-10-11  
Registry source: `src/content/lessons/index.ts`  
Registered lessons reviewed: 16

## Registry-wide findings

- The four curriculum pillars are Plan & Budget, Save & Manage, Understand Investing, and Stay Safe. Lesson and module concept IDs are maintained in `src/content/curriculum/pillars.ts` and each lesson file. There is no standalone concept graph or reusable concept explanation registry; the full explanations currently live in lesson stages.
- Every registered lesson has bilingual lesson-stage text and objectives, one tailored explanatory visual, a working interaction or simulator, and a mastery check with at least three questions. `src/tests/curriculum.test.ts` checks these registry-wide requirements.
- Stage text now renders headings, lists, emphasis, links to HTTPS sources, and the subset of math syntax used by the curriculum. The lesson experience saves the active stage, visited stages, and objective evidence in local storage. Quiz selections themselves are not restored after a reload; the quiz can be attempted again.
- Completion is gated on correct answers to every question in a knowledge-check stage. Feedback shows the correct answer and explanation, and completion records evidence against the objective's declared evidence type.
- The curriculum uses fictional amounts and explicit assumptions in its interactive models. Several legacy simulators still contain English-only controls and explanatory copy; see the cross-curriculum limitations below.

## Verification evidence

- `npm test -- --pool=threads --maxWorkers=1`: 55 tests passed (5 files), including smoke checks for each primary route and every registered lesson route. The single-worker setting avoids a Windows/Vitest temporary-module `ENOENT` that occurred with the default parallel run in this sandbox.
- `npm run build`: TypeScript and production build passed. Vite reported a large main JavaScript chunk (~1.20 MB before gzip; ~332 KB gzip), which remains a code-splitting opportunity.
- Focused React tests cover stage persistence/resume and accurate progress percentage, quiz retry and completion gating, and each of the six newly added mini-labs.
- Browser verification was attempted with the local Vite server at `127.0.0.1:5173` and `localhost:5173`; the in-app browser returned `ERR_CONNECTION_TIMED_OUT`, and the localhost HTTP request also timed out. The local desktop browser was unavailable through the current computer-use session, so route-by-route visual checks, console checks, and actual device/zoom checks remain unverified.

## Remaining gaps to close in a follow-up

1. Localize the existing `EnhancedSIPCalculator`, `MarketIndicesLab`, `CompanyFinancialsLab`, `FinancialRatiosLab`, and `RDCalculator` controls and explanatory copy. Lesson content, visual models, quiz questions, and several older simulations already switch to Telugu, but these legacy controls do not.
2. Add a dedicated recap/transfer stage or a richer completion recap with formulas, misconceptions, and a new scenario. The current completion view summarizes objective evidence and suggests next lessons, but many lesson files do not contain a separate recap stage.
3. Build a standalone concept graph/content registry, since concept IDs are currently labels connecting lesson and module metadata rather than full concept records with their own explanations and source references.
4. Add diverse item types and per-option misconception feedback. The checks now contain three questions each, but most are multiple choice and feedback does not yet explain every distractor individually.
5. Verify routing, mobile/tablet layouts, keyboard flow, browser console output, and each legacy simulator in a real browser when the local app can be opened by the available browser surface.
